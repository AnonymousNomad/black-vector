# BLACK VECTOR — AUTONOMOUS CLOUD PRODUCTION QUEUE

Do not wait for the operator between ordinary production phases.

Complete a bounded phase:
implement → verify → fresh review → repair → commit → push → log → continue.

Stop only for:
- data-loss risk;
- destructive repository requirement;
- unrecoverable source/canon contradiction;
- unresolvable asset-license problem;
- persistent save corruption;
- systemic engine/runtime failure without bounded repair;
- genuine creative fork with materially different valid outcomes;
- missing secret/device when that specific gate cannot be truthfully completed.

Do not stop because:
- a phase ended;
- a commit was made;
- a test initially failed with a bounded cause;
- an implementation detail needs an engineering choice.

## Program objective

Advance BLACK VECTOR into a substantial, coherent, high-quality playable tactical-survival game based on the approved production design already in the repository and recovered handoff.

Do not rebuild it as a different game.

Core loop:

SURVIVE
→ EXPLORE
→ OBSERVE
→ LEARN
→ CHOOSE APPROACH
→ ACT
→ WORLD RESPONDS
→ LIVE WITH CONSEQUENCES.

## Phase 3 — Human AI + routines

Move humans beyond stationary watcher behavior.

Support:
- routine;
- idle;
- travel;
- inspect;
- interaction/conversation hooks;
- perception;
- suspicion;
- investigation;
- search;
- alert;
- coordination;
- plausible return to routine.

NPCs exist for reasons independent of Corley.

- what they believe;

Exit:

## Phase 4 — Perception + stealth

Ground stealth in world conditions:

- line of sight;
- distance;
- movement;
- stance;
- lighting;
- terrain;
- occlusion;
- vegetation;
- sound;
- surface;
- weather;
- water/noise masking;
- recent evidence.

Use bounded awareness progression such as:

unaware
→ noticed anomaly
→ suspicious
→ investigating
→ possible person
→ confirmed person
→ alert

Detection and identity confidence remain separate.

Do not replace this with one magic universal visibility number.

Exit:
observation, patience, route choice and environmental understanding materially change outcomes.

## Phase 5 — Evidence, knowledge, heat + consequence

Implement/complete:
- evidence discovery;
- evidence persistence;
- imperfect human information propagation;
- regional/institutional heat;
- identity confidence;
- suspected-actor state;
- local consequence;
- believable escalation/de-escalation;
- no global omniscience.

World reaction must connect to actual player choices.

Exit:

## Phase 6 — Grounded combat + physiology

Combat must:
- exist;
- be avoidable where appropriate;
- remain human-scale;
- interact with injury/physiology;
- avoid universal arcade-HP abstraction as the only state;
- affect later decisions and world state.

Implement only the combat depth required for the approved playable product.

Do not widen into a giant firearms simulator.

Include:
- basic combat stance/response;
- hit/recoil/injury state;
- mobility consequence;
- recovery/medical implications where canonical;
- equipment relevance;
- non-terminal failure where supported.

Exit:
combat is tense, dangerous, readable and optional in situations designed for alternatives.

## Phase 7 — Tactical problem + multiple solutions

Create/complete at least one substantial emergent tactical objective.

It must support materially different approaches, e.g.:
- observe and avoid;
- deceive;
- infiltrate;
- manipulate environment;
- negotiate/interact where canonical;
- disable/restore systems;
- direct confrontation as one option, not the default.

Outcome must feed:
- evidence;
- knowledge;
- heat;
- relationships/state;
- later world response.

Exit:
the player can solve the same problem differently and live with distinct consequences.
