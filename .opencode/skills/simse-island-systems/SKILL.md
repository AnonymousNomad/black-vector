# SIMSE SOUND ISLAND SYSTEMS (BV-SKILL-029)

## NAME
SIMSE SOUND ISLAND SYSTEMS

## PURPOSE
Own the systemic island law of Saga 1 as frozen by Directive 015 (`docs/design/SIMSE_SOUND_SURVIVAL_ENVIRONMENT_HORROR_BIBLE.md`): the island is a living, propagating system, not a sequence of combat levels. This skill composes (never replaces) the specialist skills — survival (017), horror (018), affordances (006), sectors (013), facilities/ally (020), population ecology (027), prologue (028) — by owning the frame they all feed through: interaction classes, consequence law, propagation graph, community state, the five-facility systemic anchors, edge-device coarse model, and survival-HUD information ownership.

## WHEN TO LOAD
- Any world-system work on Simse Sound Saga 1: infrastructure, power/heat/communications, world-state propagation, community/systemic state, facility network consequences.
- Designing/placing consequential interactive objects or interaction classes (power/access/communication/shelter/heat/medical/transport/tool/information/world-state).
- Reconciling what a restored facility does to the island (dependency + secondary consequences), or what a community is owed and charged.
- Any survival HUD information-ownership question (what is always visible vs contextual vs diagnostic).
- Edge-device feasibility of any world-system/off-screen simulation model.

## DO NOT LOAD WHEN
- Survival subsystems implementation (BV-SKILL-017 owns cold/wetness/exertion/forest/weather internals).
- Horror/perceptual event authoring (BV-SKILL-018; this skill only feeds it cadence/state).
- Facility pipeline stages under BV-SKILL-020; population/NPC authoring under BV-SKILL-027; sector activation under BV-SKILL-013.
- Opening/prologue architecture (BV-SKILL-028).

## PRECONDITIONS
- Governing set loaded.
- D015 bible current; facility roster (D004 §4 / doctrine §31), community archetypes (D011 §16), no-omniscience truth (D011 §7), and the save/obs contract (SOP-006) are canonical. Other directives' bibles are consulted for the thing being changed.

## GOVERNING INVARIANTS
1. FOUR ISLANDS: Simse Sound is simultaneously NATURAL / HUMAN / PROGRAM / IMPOSSIBLE on the same geography; content is authored across the interpretations it serves, and the impossible never replaces the other three (bible §3).
2. CONSEQUENTIAL INTERACTION ONLY: interaction changes survival, access, information, population behavior, infrastructure, environmental safety, faction pressure, future routes, resource availability, or horror state. Decoration must read as decoration; every consequential interaction is observable with a reason (SOP-006).
3. INFRASTRUCTURE CONSEQUENCE LAW (frozen, extends D013 four-term law): every restore carries BENEFIT + COST + FAILURE STATE + DEPENDENCY + SECONDARY CONSEQUENCE. No pure improvements, ever (bible §17/§23).
4. WORLD-STATE PROPAGATION IS BOUNDED + EVENT-DRIVEN: a small set of nodes with declared edges (trigger, delta, latency, cost); no global simulation, no per-frame simmer, no omniscience (information propagates only across declared edges with latency, exactly like the Shade network — D011 §7).
5. POWER PRIORITY IS DESIGN: restoreable loads are scheduled in-fiction (heat vs medbay vs workshop vs comms vs security); not every facility runs everything at once; each choice costs fuel/signature/failure risk (bible §19).
6. COMMUNITY LIABILITY LAW: every benefit to a community carries a cost, failure state, dependency, or secondary consequence — no free goodwill (bible §23).
7. FIVE-FACILITY ROSTER CLOSED (F1 Gyle Cannery · F2 Tanellus Station · F3 Frostvane Relay · F4 Vivara Mine · F5 Black Hand Annex): no additions; each is a systemic anchor with dependencies that make restoration a network, not a list (bible §24).
8. SAGA-1 CONTAINMENT: D015 designs Saga 1 Simse Sound only; future-franchise material (Saga-3 protagonist, real-island captivity, cosmic/lunar systems, late hybrid transformation, the constructed-reality twist) is excluded from this design frame; only the small seam budget (§48) may exist and must stay invisible and non-required.
9. EDGE-DEVICE BOUNDED: world systems are compatible with Android/tablet + GL Compatibility: sector activation, bounded populations, event-driven simulation, coarse off-screen states (SAFE/ACTIVE/THREATENED/DISPLACED/LOST), pooled effects, selective weather complexity, scripted high-value horror (bible §28).
10. SURVIVAL HUD OWNERSHIP (frozen): near-permanent CONDITION/CORE TEMPERATURE/EXERTION/CONTROL (+ NEURAL STRAIN later); contextual conditions; diagnostic screen for body diagram/clothing/forecast/world-state. HUD confirms diegetic feedback, never replaces it (bible §45/§46).

## WORKFLOW
1. Read the D015 bible current state + the facility/community/population canon for the target system; confirm no retcon is needed (bible Appendix A discipline).
2. Identify which ISLAND(s) the change touches; author across them where warranted.
3. Classify the interaction (bounded classes only); assign the consequence law terms (benefit/cost/failure/dependency/secondary) BEFORE design is accepted; record state + reason for observability (SOP-006).
4. Trace propagation: does the change have a declared edge with trigger/delta/latency/cost? If not, the propagation does not exist this directive — write nothing that reads as global sim.
5. Compose cross-skill: route survival internals to 017, horror to 018, facility stages to 020, population to 027, sectors to 013 — this skill only defines the systemic frame.
6. Check edge-device fit (bible §28 budgets) and survival-HUD ownership (bible §45). Validate; update doctrine only with durable law, candidate content stays labeled CANDIDATE.

## IMPLEMENTATION GUIDANCE
- World-state graph = data/resources (nodes: facilities/communities/networks; edges: trigger/delta/latency/cost), consumed by sector activation (013), facility pipeline (020), and observability overlay (015). No per-frame world sim.
- Electrical abstraction is a game-facing fiction: source → distribution → local circuit → device group; player tasks are restore/reroute/isolate/pick priority load, never real electrical work.
- Facility restoration is a NETWORK goal (F5 converges on F2/F3/F4 contributions), not a standalone checklist; dependency shapes gate the pipeline (020).
- Storms are island-scale events, authored/forecastable, creating tactical opportunity as well as danger; weather is one truth consumed by all systems (017/014).
- Every authored horror event consumes the cadence from weather/isolation (018) and must carry the bible §39 field set — or it is not an authored event.
- Retrospective seams (bible §48) are moods/recurrences filed for a later meta directive; never explained, never required for S1 comprehension.

## ANTI-PATTERNS
- Freeform/universal object interaction; decorative "interact prompt" world (bible §4).
- Pure-improvement restoration (success with no consequence — law §3).
- Global simulation / per-frame world simmer / omniscient propagation (law §4).
- Facilities beyond the closed F1..F5 roster; outposts creeping into sixth bases (017/020 scope).
- Evaluating system value without the survival-HUD ownership table (bible §45).
- Importing post-Saga-1/future-franchise material into a Saga-1 design (law §8).

## KNOWN FAILURE MODES
- Propagation edges become sprawling (scope explosion) → keep the declared-edge list small; anything without a trigger/delta is removed (bible §21).
- One-benefit dominance in facilities (restore = always correct) → re-apply consequence law or the decision collapses (bible §17 fixture check).
- Coarse off-screen state drifting into "actually simulated" (tablet cost) → enforce coarse STATE v. near-player full simulation (bible §28).
- HUD creep (conditions becoming bars) → re-check §45 ownership table.

## VERIFICATION
- Static: every accepted restore/interaction carries the consequence-law terms and an observability reason; propagation edges declared; roster = F1..F5; off-screen model coarse; survival HUD ownership per §45; no future-franchise terms leaked into S1 prompts.
- Cross-skill: no invention of parallel survival/horror/facility/population systems — internal scope routes through the existing owners.
- Tooling: run `tools/validate_methodology.py` + `tests/static_verify_game.py` after any canon change.

## STOP CONDITIONS
Stop if a system requires global simulation, omnidirectional consequences, facility-creep beyond five, pure-benefit restoration, omniscient propagation, or imports Saga-3/future content into Saga 1 — re-anchor to D015 bible sections cited above before continuing.
